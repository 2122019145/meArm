# meArm 四自由度机械臂固件（Arduino Uno）

一套跑在 Arduino Uno（ATmega328P，16 MHz）上的完整固件：摇杆手动 + 串口控制 + 三物体自动取放
+ 7 种绘图任务 + 录制回放，附带 PC 端 11 个回归探针与 AVR 真编容量记录。

当前版本 **v1.6.7**（tag [`v1.6.7`](https://github.com/2122019145/meArm/releases/tag/v1.6.7)，已发布）；
上一发布版 [v1.6.5](https://github.com/2122019145/meArm/releases/tag/v1.6.5)。
v1.6.7 把**整套运动逻辑换成参照工程 `Fifiiiii-123/MeArm@a7d2ee1` 的那一版**：底盘顶面中心为原点、
真实 mm 尺度（`L1 = 38`、`L2 = L3 = 80`）、单分支反解、机械行程窗口；取放点位表与绘图参数
都按新尺度重新标定过。逐条见 [运动学模型](#运动学模型) 与 [v1.6.7 运动逻辑替换](#v167-运动逻辑替换)。

**一套源码，两种交付形态：**

- **多文件版**：仓库根目录 21 个文件（`meArm.ino` + 9 个 `.cpp` + 11 个 `.h`），工程形态，日常开发只改这里；
- **单文件版**：`single/meArm/meArm.ino`（LF 换行），由 `.selfcheck/make_single.ps1` 从多文件版
  **生成**，交作业/考试直接交这一个文件。v1.6.7 换模型后已重新生成过一次；字节数与行数
  以在本机实跑 `make_single.ps1` 的结果为准（不在文档里写死，免得又对不上）。

> 单文件版是生成物，不要手改。改完根目录源码后必须重跑 `make_single.ps1`，
> 否则 `.selfcheck` 里的 `wearm_ino_test` 探针会立刻失败。

详细设计说明（1500+ 行中文，含每个决策的理由与上机确认清单）在
[`.selfcheck/README.md`](.selfcheck/README.md)。

## 硬件与接线

| 部件 | 引脚 | 说明 |
| --- | --- | --- |
| 基座舵机 b（angle1） | **D9** | 回转，电气行程 0~180°；本工程行程窗口 0~180° |
| 上臂舵机 r（angle2） | **D8** | 俯仰，电气行程 0~180°；本工程行程窗口 **45~160°** |
| 下臂舵机 c（angle3） | **D7** | 俯仰，电气行程 0~180°；本工程行程窗口 **30~110°** |
| 夹爪舵机 f（angle4） | **D6** | 电气行程 0~180°；名义张开 150°、合拢 60°、夹紧 45° |
| 左摇杆 X | **A0** | → 基座 b |
| 左摇杆 Y | **A1** | → 上臂 r |
| 右摇杆 X | **A2** | → 夹爪 f（绘图示教点动时默认不驱动） |
| 右摇杆 Y | **A3** | → 下臂 c |
| 指示灯 | **D13** | 板载 LED：任一关节在动则快闪，全部静止则灭 |
| 四个物理按键 | D2\~D5 | 默认**完全不读**（`WEARM_BUTTON_PINS=0`），功能全走串口孪生命令 |
| 串口 | D0/D1 | **115200-8N1**，行尾可选，静默 300 ms 即提交该行；单字符命令一到就执行 |

- 舵机由 **Arduino 原生 `Servo` 库**驱动（标准 20 ms 一帧，4 路）；v1.6.6 之前是
  Timer1 硬件 PWM 直驱（30 ms 帧），换回原生库是为了夹爪堵转时保持力矩更稳，
  代价约 +1200 B flash。`servo_drive` 仍是唯一出口，换实现只改那一个文件。
- 基座与夹爪是**反向装配**，在唯一出口 `writeServo()` 里做镜像：基座 `180 − b`、
  夹爪 `TOOL_MIRROR_SUM(210) − f`；换装配只改 `WEARM_MIRROR_*`，逻辑角不用动。
- 【v1.6.7】上臂/下臂也各有镜像开关，但**镜像和不再是 180**（`r`/`c` 的行程窗口不对称，
  写死 180 会把 `r = 45` 映成 135 越界）：上臂 `(KIN_RARM_MIN+KIN_RARM_MAX) − r = 205 − r`、
  下臂 `(KIN_FARM_MIN+KIN_FARM_MAX) − c = 140 − c`。三路都可以**运行时翻转**：
  `g_mirrorBase` / `g_mirrorShoulder` / `g_mirrorElbow`（定义在 `serial_protocol.cpp`），
  串口用 `m` 查询、`mB` / `mS` / `mE` 就地切换，掉电不保存。
  **本机实测结论：基座旋向、上臂 `alpha = 180 − r`、下臂 `beta = c` 三条都对，
  不需要 `mB` / `mS` / `mE`**，默认值即为正确组合（基座 1、上臂 0、下臂 0）。
- 上臂/下臂的引脚在 v1.6.5 开发中调换过（现固件为 ch1 = D8 上臂、ch2 = D7 下臂）；`setup()` 已按此接线绑定。
- 上机若出现某个关节抖动，优先排查舵机供电与共地，而不是先改固件
  （分析见 `.selfcheck/README.md` 的抖动附录）。

## 运动学模型

**v1.6.7 起运动逻辑整体换成参照工程的那一版**（来源与替换理由见下一节
[v1.6.7 运动逻辑替换](#v167-运动逻辑替换)）。单位一律 **mm**，
**坐标原点在底盘顶面中心**：z = 0 就是底盘顶面，肩轴在 z = +38。

几何参数（`constant_and_positions.cpp` 的 `struct arm arm1`）：

| 符号 | 值（mm） | 含义 |
| --- | --- | --- |
| `L1`（`armheight`） | 38 | 底盘高：底座顶面 → 肩轴 |
| `L2`（`armLength1`） | 80 | 上臂：肩 → 肘 |
| `L3`（`armLength2`） | 80 | 前臂：肘 → 腕（末端） |

即 `arm1 = { 80, 80, 38 }`；水平臂展 `L2 + L3 = 160`。

**关节角约定**（舵机中立位 90°；`f` 只驱动夹爪，不参与正反解）：

| 符号 | 含义 | 与舵机角的关系 |
| --- | --- | --- |
| `theta` | 基座转角，**自 +y 量起** | `theta = b − 90`（所以 `b = 90°` = 正前方 +y） |
| `alpha` | 上臂仰角（水平为 0、向上为正） | `alpha = 180 − r` |
| `beta` | 前臂相对肘部的折角 | `beta = c` |

**正解**（`constant_and_positions.cpp` 的 `recFromServo()`；三角函数的参数是弧度）：

```
theta = (b − 90)·PI/180
alpha = (180 − r)·PI/180
beta  =  c·PI/180
R_h   = L2·cos(alpha) − L3·cos(alpha + beta)      # 末端到基座轴的水平距离
x     = −R_h·sin(theta)
y     =  R_h·cos(theta)
z     = 38 + L2·sin(alpha) − L3·sin(alpha + beta)
```

**反解**（同文件 `getAngleEx()`；单分支 `+acos`，**没有镜像分支**，
也不再有 `ikBranch()` / `normRevAngle()` 那套四候选优先级）：

```
rho = √(x² + y²)
d   = √(rho² + (z − 38)²)          # 末端到肩轴的距离
判据：d ∈ [ |L2−L3| + 1 , L2+L3 − 1 ] = [ 1, 159 ] mm，不满足就拒解
cosB  = (L2² + L3² − d²) / (2·L2·L3)      # 先夹到 [−1, 1]
beta  = acos(cosB)                        # 只有这一个分支
phi   = atan2(z − 38, rho)
alpha = phi + atan2( L3·sin(beta), L2 − L3·cos(beta) )
R_h < 5 mm 视为奇异（末端几乎压在基座轴上），拒解
theta = −atan2(x, y)
b = theta·180/PI + 90 ,  r = 180 − alpha·180/PI ,  c = beta·180/PI
```

解出的 `b/r/c` 再夹到下面的行程窗口，**然后用夹取后的角度重跑一遍正解做残差核对**：
本工程照抄参照仓库的**水平**残差 `√(dx² + dy²) > 5.0 mm` 判失败
（`constant_and_positions.cpp`，与 `Task5_LineN2_TeachSmooth.ino:237-239` 逐点等价；
z 被夹取推偏而 x/y 正常的点照样接受，只多打一条日志提示）；
一个候选都不合格就是反解失败，失败时**一个字节都不改**（契约：姿态保持原样）。

**行程窗口**（宏在 `constant_and_positions.h`，取自参照仓库的实机标定值）：
它**不是舵机的电气行程**（那是 0~180°），而是这台实物三个位姿关节的**机械行程**，
最后一道防线，防止结构自己顶死（上臂完全放平、前臂反折等姿态会撞到自身）：

| 关节 | 宏 | 窗口 |
| --- | --- | --- |
| 基座 `b` | `KIN_BASE_MIN` / `KIN_BASE_MAX` | 0° ~ 180° |
| 上臂 `r` | `KIN_RARM_MIN` / `KIN_RARM_MAX` | 45° ~ 160° |
| 下臂 `c` | `KIN_FARM_MIN` / `KIN_FARM_MAX` | 30° ~ 110° |

反解结果超出行程时按参照仓库的做法**夹到窗口边界**（不是拒绝），随后那 5 mm 回代
核对会告诉你"夹取后的实际到达点"和目标的偏差；`moveJointStep()` 也引用同一组宏。

**可达半空间是 y ≥ 0**：`b ∈ [0°, 180°]` 即 `theta ∈ [−90°, 90°]`，而 `y = R_h·cos(theta) ≥ 0`；
`x` 可正可负。也就是说**前后是 y、左右是 x** —— 旧模型的可达侧是 `x ≥ 0`，
正好是绕基座轴转 90° 的关系（旧 `x` 对应新 `y`、旧 `y` 的绝对值对应新 `x`）。

**上电初始位姿** `POS_HOME = (0, 80, 118)`（`constant_and_positions.cpp`），
对应关节角 `(b, r, c) = (90, 90, 90)`、夹爪半开（两节都取 90°）：**上臂竖直向上、
前臂水平朝前**，正解 / 反解严格互逆。注意它落在工作空间**中央**，
不再像旧模型的 `(40, 0, 0)` 那样贴在可达外边界上。

**工作空间盒子**（同文件 `struct rangeLimit limit`）：`x` / `y` ∈ **±160**
（= ±(L2+L3)）、`z` ∈ **[−18, +171]**（**实测可达竖直带**，自底盘顶面量；实测边界是
`[−18.5, +171.5]`，盒子各留 0.5 mm 余量）。两端都不是臂长的几何极限 `[−122, +198]`，
而是**关节行程**决定的（见下面的可达性一节）：`r ∈ [45,160]` ⇒ `α ∈ [20°,135°]`
使上臂压不到水平线以下，`c ∈ [30,110]` ⇒ `d ≤ 131.1 mm`。盒外的点报"越界"、
盒内但姿态不可达的点报"够不到"，语义各自清楚。
它仍然只是给外部的**粗坐标范围**，真正的可达性由上面的 `d` 判据、奇异判据、
行程窗口与 5 mm 回代残差（只查水平 x/y，与参照工程一致）共同把关。

> **这个盒子比反解严，是有意的**：反解只查水平残差，在"前臂已顶到行程端点、
> 水平 OK、竖直差很远"的近满伸区它会放行 —— 实测 `(0, 122, −42)` 解出
> `r=160 / c=110`，真实到达 `(0, 126.6, +4.08)`，**竖直误差 +46.1 mm**；
> `(0, 122, −60)` 落到同一组角，误差 +64.1 mm。所以"反解接受"不等于"真能到"，
> 盒子与路径校验（`path_core.h`）、点动（`move.cpp` 的 `posOutOfRange`）都按
> 物理可达带判，把这些"竖直撒谎"的解挡在取放/绘图路径之外。

**关节角是唯一真值**：摇杆、串口、按键、取放、绘图五条入口最终都只改 `Pos.ser.angle1..4`，
再调 `recFromServo()` 刷新派生坐标 `Pos.rec`（只用于显示与工作空间校验）；
笛卡尔移动统一走 `moveToPoint()`，三个关节的行程钳制在 `moveJointStep()` 里。

> **注意语义变迁**：串口 `x,y,z` 写的是**三个舵机角度，不是末端坐标**。
> v1.3.0\~v1.6.3 曾是末端坐标版本，备份在分支 `backup/xyz-cartesian`（即 tag `v1.6.3`）与 `dist/`。

## v1.6.7 运动逻辑替换

**来源**：`https://github.com/Fifiiiii-123/MeArm`，commit **`a7d2ee1`**；
本地只读参照克隆在 `others/f/MeArm`。该仓库里从 `Task5_LineN` 起，经
`LineN_Mirror` / `LineN2` / `_Fixed` / `_Fixed2` / `_Lift` / `_Lift2` / `_Lift3` /
`_PauseFix` / `_PauseFix2` / `_PauseFix3` / `_PauseFix4` / `_TeachDir` / `_TeachFix` /
`_TeachSmooth` 这一系列草图的 `solveIK` / `forwardKin` / `servoToGeo` **逐字节相同**，
链尾是 `Task5_LineN2_TeachSmooth/Task5_LineN2_TeachSmooth.ino` ——
本工程采用的正是这一版运动逻辑。

**新模型一句话**：原点在底盘顶面中心、z = 0 是底盘顶面、肩轴在 z = +38（mm）；
`L1 = 38`、`L2 = L3 = 80`；`theta = b − 90`（自 +y 量起，`b = 90°` = 正前方）、
`alpha = 180 − r`、`beta = c`；正解 `R_h = L2·cos(alpha) − L3·cos(alpha+beta)`、
`x = −R_h·sin(theta)`、`y = R_h·cos(theta)`、
`z = 38 + L2·sin(alpha) − L3·sin(alpha+beta)`；反解单分支 `+acos`，
判据 `d ∈ [1, 159] mm`、`R_h < 5 mm` 判奇异、`theta = −atan2(x, y)`，
再钳行程窗口（`b 0~180`、`r 45~160`、`c 30~110`）并用钳后的角度重跑正解，
**水平残差 > 5.0 mm 判失败**（照抄参照仓库的判据）；`POS_HOME` 由 `(40, 0, 0)` 改成 `(0, 80, 118)`
（同一个物理姿态，仍是 `(b,r,c) = (90,90,90)`）。逐条公式见上一节。

**旧模型为什么被整体替换**（v1.6.7 之前文档里的那些描述全部作废）：

- 旧模型 `arm1 = { 20, 20, 0 }`、1 工作区单位 = 4mm，等于把实际 160mm 的臂展写成 40mm，
  坐标数值与实物差一个数量级；
- 旧约定 `b = 90°` 指向 **+x**，而全工程又约定"x = 左右、y = 前后"，
  两者自相矛盾（+x 被当成"开机面朝方向"）；旧 `alpha = 90 − r`、`beta = c − 90`、
  `theta = 90 − b` 与实物姿态也对不上；
- 旧 `POS_HOME = (40, 0, 0)` 正好**贴在可达外边界** `rho = 40` 上：从 home 向外伸不了、
  也抬不起来，取放模块不得不为它写特例；
- 旧反解是 `ikBranch()` 四候选优先级 + `normRevAngle()` 折回 360°，
  且 `b ∈ [0°, 180°]` 只覆盖 `x ≥ 0` 半空间，`x < 0` 的点反解直接失败。

**新臂展 160mm 的意义**：`L2 + L3 = 160mm` 是实物尺度（旧文档里的 40 是"20 单位"的假尺度），
坐标第一次与实物成 mm 级对应，取放/绘图的点位可以直接拿卷尺量。代价是旧的
`x/y ±40` / `z ±60` 盒子、旧取放点位表、旧纸面中心 (27, 0)、旧纸面高度 −20
全部作废：取放点位表已按"整张表绕基座轴刚体旋转 90°"重标（见 [自动取放](#自动取放)），
绘图参数已按新的可达集重选（见 [绘图](#绘图)）；**纸面高度必须上机用 `p<z>` 重标**
——默认 `DRAW_PEN_Z_DEFAULT = −6.0` 是"最低能放进 50×50mm 图形"的平面，
实物纸面（铺在台面上）比它低得多，所以画图前要**把纸垫高**（见 [绘图](#绘图)）。

**上机已确认**（本机实测）：基座旋向、上臂 `alpha = 180 − r`、下臂 `beta = c` 三条都对，
**不需要 `mB` / `mS` / `mE`**；`WEARM_MIRROR_BASE` 保持默认 1，
`WEARM_MIRROR_SHOULDER` / `WEARM_MIRROR_ELBOW` 保持默认 0。

## 控制方式

### 摇杆（默认启用的手动方式）

一路摇杆轴对应一个关节，可同时操作：

| 摇杆轴 | 关节 | 方向 |
| --- | --- | --- |
| A0（左手柄左右） | 基座 b | 角度增大 = 末端**向左**（朝 −x）转；`b = 90°` 正对前方 +y |
| A1（左手柄前后） | 上臂 r | 前推 = 角度减小 → `alpha = 180 − r` 增大 = 上臂抬高 |
| A3（右手柄前后） | 下臂 c | 前推 = 角度减小 → `beta = c` 减小 = 前臂相对肘部伸直 |
| A2（右手柄左右） | 夹爪 f | 角度增大 = 张开；推右 = 夹紧 |

- 每格位移 = `speed.stepSize × 偏转幅度/500`，关节下限 0.1°；步间间隔固定为 `speed.stepDelayMs`
  （推得狠一步更远，节奏不变）。
- 中位在开机时自标定（每轴平均 32 次 ADC）；标定期间不要碰摇杆。
- 防乱摆四层：死区 40、开机自标定、运行期 ±1 计数慢跟踪、施密特迟滞。
- 取放 / 录制回放 / 绘图期间摇杆整体让位；录制期间摇杆照常可用。

### 串口

115200-8N1。同一行里所有轴一起写入并只刷新一次正解；未写的轴保持不动。
**取放、录放、绘图期间不排队**：只接受"活字符"（见下），其余命令直接回 `BUSY`。

### 物理按键（默认关闭）

本工程把按键功能全部做成串口孪生命令，物理按键默认连 `pinMode` 都不做 ——
因为 D2 上还接着右摇杆的 SW，前推到底会误触发"按键 1"抢走手动控制。
需要实体按键时用 `-DWEARM_BUTTON_PINS=1`：1 = 循环取放 A→B→C，2 = 录制开关，
3 = 播放，4 = 回中。

## 串口命令

| 命令 | 作用 | 回复 |
| --- | --- | --- |
| `O` / `S` | 夹爪张开（150°）/ 合拢（60°，不带夹紧过行程） | `OK` |
| `H` / `L` | 速度升 / 降一档 | `OK` |
| `x[,y,z]` | **写三个舵机角度**：x→基座 b、y→上臂 r、z→下臂 c。可带 `=`、可小数、可 ±、大小写不敏感、可只写部分轴、重复轴以最后一个为准；越界按各自的**行程窗口**夹取（b 0~180、r 45~160、c 30~110，如 `y20` 写 45）而不是拒绝 | `OK` |
| `A` / `B` / `C` | 启动 A / B / C 取放序列 | `OK` 或 `BUSY` |
| `N` / `R` / `P` / `M`、`0` | 按键孪生：循环取放 / 录制开关 / 播放 / 回中（带尾巴一律 `ERR`） | `OK` / `BUSY` / `DISCARD` / `EMPTY` |
| `F` | 循环切换绘图任务 | `OK F=<tag>` |
| `D` / `G` / `E` / `Q` / `U` / `W` | 开始绘图 / 记示教点 / 撤销 / 暂停 / 继续 / 取消 | `OK`，或 `BUSY` / `REJECTED` |
| `p<z>` / `n<半宽>` / `o<x>,<y>` | 标定纸面：高度（默认 **−6.0**，自底盘顶面量、单位 mm，**必须上机重标**；只拒绝 NaN，任意有限值都接受）/ 图形半宽（8~48，默认 25）/ 中心（\|x\|,\|y\| ≤ 140，默认 0,75） | `OK` 或 `REJECTED`（且不改参数） |
| `!` | 查询已编译且启用的模块 | 恰好一行 `P=1 B=1 D=1` |
| `!P` / `!B` / `!D` | 运行时开关取放 / 按键 / 绘图 | 切换后回同一行；模块未编译则 `REJECTED` |
| `m` / `mB` / `mS` / `mE` | 查询 / 就地翻转**基座 / 上臂 / 下臂**的物理换向（运行时方向标定，只改 `writeServo()` 送出的数，逻辑角与反解不变，掉电不保存；不移动机械臂，任何时刻都接受） | 恰好一行 `B=1 S=0 E=1` |
| 其他 | — | `ERR` |

回复原语一共 7 种，别只看 `OK` / `ERR`：

| 回复 | 含义 |
| --- | --- |
| `OK` | 命令已执行 |
| `ERR` | 语法错（角度写坏、单字符命令带尾巴等） |
| `REJECTED` | 该功能**没编译进来**；或绘图轨迹校验不过 |
| `BUSY` | 看懂了，但机械臂在忙 / 取放启动被拒（状态零改动） |
| `DISCARD` | `R` 结束录制但数据不合格（无位移、无动作、缓冲满） |
| `EMPTY` | `P` 时没有任何录制数据 |
| `OFF` | 功能在固件里，但被 `!P` / `!B` / `!D` 关掉了 |

`F` 与 `m` 的回复是带参数的 `OK` 变体（`OK F=LINE`、`B=1 S=0 E=1`），
`!` / `!P` / `!B` / `!D` 也走 `P=1 B=1 D=1` 这种形式。`O` / `S` 自 v1.6.6 起只回 `OK`，
不再附带夹爪角度（开机横幅里的 `ANG` 一段同时也删掉了）。

开机横幅会打印全部命令首字符：
`CMD OSHL ABC NRPM0 FDGEQUW pno ANG ! !P !B !D m mB mS mE`。

**忙时仍接受的字符**（位图 `s_liveBits`）：`0 D E F G H L M N P Q R U W n o p`，
另有 `1`/`2`/`3`（旧调速档位直达键，已删，位图里有意留着这三个位，收到干净的 `ERR`）。
也就是说忙时 `O`、`S`、`x/y/z`、`A/B/C` 一律回 `BUSY`。
`m` / `mB` / `mS` / `mE` 不走忙判定（换向不移动机械臂），所以位图里没有它们。

## 自动取放

| 物体 | 取点 (x, y, z) | 放点 (x, y, z) | 位移 |
| --- | --- | --- | --- |
| A | (69.0, 58.0, 20.0) | (36.0, 77.0, 20.0) | 水平 38.1 |
| B | (−69.0, 58.0, 60.0) | (−36.0, 77.0, 60.0) | 水平 38.1 |
| C | (0.0, 105.0, 100.0) | (0.0, 75.0, 100.0) | 水平 30.0 |

（单值真值是 `pick_place.cpp` 的 `PICK_SRC` / `PICK_DST`，单位 mm、自底盘顶面量。
三个取点高度分别是 +20 / +60 / +100，即"台面上 2cm / 垫高 6cm / 垫高 8cm"，放点与取点同高。
**这张表不是从旧表换算来的**：新模型的可达集被**关节行程**卡得比臂长紧得多（见下），
旧表的半径与 z 都出界，所以是按 `pickPlaceStart()` 的完整判据重新搜出来的 ——
工具 `.selfcheck\picktable_search.cpp`（判据与固件逐字一致），
`.selfcheck\picktable_run.cpp` 再用固件本体把 A/B/C 三条完整序列各跑一遍。
旧表（`{24,16,−20}` / `{24,−12,0}` / `{26,0,20}`，旧单位、旧可达半空间 `x ≥ 0`）
现在只有方位上的参考价值：把旧表绕基座轴**刚体旋转 90°**
（新 `x` = 4×旧 `y`、新 `y` = 4×旧 `x`）就是新表三个取点所在的方位，
但半径要按新可达集收回 90\~105mm、z 要抬到 +20 以上。）

- 高度与飞行：`PICK_LIFT_DZ = 50.0`（5cm，理想的接近 / 撤离 / 平移飞行高度）、
  `PICK_CLEAR_DZ = 10.0`（1cm，飞行高度下限，再低会蹭到物体）、
  `PICK_BACK_DZ = 20.0`（2cm，物体"后方"的水平退让）、
  `PICK_TRAVEL_STEP = 5.0`（0.5cm，飞行高度逐档下降的步长）、
  `PICK_HEIGHT_MIN/MAX = −18.0 / +171.0`（物体高度窗口 = 实测可达竖直带，见上文）。
  物体越高、水平半径越大，"物体高度 + 5cm"越做不到，`planTravelZ()` 会按 5mm 逐档
  降到刚好可行，最低不低于"最高物体 + 1cm"；本表实测三档飞行高度 A 70 / B 110 / C 115
  （C 只抬 15mm，就是这条规则在生效）。
- 可达性（真正的约束是**关节行程**，不是臂长）：
  `d² = L2² + L3² − 2·L2·L3·cos(c)`，`c ∈ [30°, 110°]` ⇒ `d ∈ [41.4, 131.1]` mm
  （两节各 80mm 几何上能到 159，但那要 `c ≈ 166°`，早就出了行程窗口）；
  `α = 180° − r`、`r ∈ [45,160]` ⇒ `α ∈ [20°,135°]`，上臂压不到水平线以下；
  再加 `y ≥ 0`。**实测可达竖直带（固件反解全程扫描，z 步长 0.5mm）只有
  `z ∈ [−18.5, +171.5] mm`，即 −1.9cm ~ +17.1cm（自底盘顶面量）** ——
  代码里 `limit` 的 z 与 `PICK_HEIGHT_MIN/MAX` 就按它取整成 `[−18, +171]`，
  用户最初要求的 −10cm ~ +30cm 两端都超出（差 81.5 / 128.5 mm），且这是
  **机构极限**：即使把 `r` 放到 180°（上臂压成水平），末端最低也只有 `38 − 80 = −42mm`，
  要到 −100mm 得上臂压过水平线（`r > 180°`，普通舵机做不到）；上界受 `d ≤ 131.1` 限制。
  本表实测 A `d = 91.9`、B `d = 92.8`、C `d = 121.9`。改点位前务必用上面那个搜索工具验一遍。
- 夹爪三段角：开 = `TOOL_ANGLE_OPEN` 150°，名义合拢 = `TOOL_ANGLE_CLOSE` 60°，
  夹紧 = `TOOL_ANGLE_TIGHT` 45°（在名义合拢角基础上再往里压 **15°**，保证小物体也
  真的被夹到）。合爪分两步走：先用 60°/s 快合到名义合拢角，再用 12°/s 慢慢压到
  夹紧角 —— 一次快合到底会让爪面像楔子一样把物体挤出去。
  **夹紧之后到张开之前的每一帧都重申夹紧角**，防止夹持力衰减。
- 速率：慢 25 / 中 50 / 快 90 °/s；夹爪快合 60 °/s、压紧 12 °/s；每阶段停顿 600 ms；
  单段限时 180\~4000 ms；路径采样 `PICK_PATH_SAMPLE_STEP = 2.0` mm、
  最多 `PICK_PATH_SAMPLE_MAX = 160` 点、分支跳变阈值 25°；启动容差 10°。
- 12 个阶段：`idle → to-src-approach → descend-src → close-tool → squeeze-tool →
  dwell-close → lift → traverse → descend-dst → open-tool → dwell-open → retreat`。
- `pickPlaceStart()` 返回 0 启动 / −1 物体非法 / −2 已在跑 / −3 姿态或路径校验不过
  （−3 有两个来源：当前位姿不在它自己坐标的反解分支上，或路径上有采样点不可达）/
  −4 物体高度落在 `PICK_HEIGHT_MIN..MAX` 之外；
  拒绝时**一个字节都不写**；启动前会先把夹爪归位到张开角，避免"闭着爪子"压下去。

编号即 `F` 的循环顺序。纸面参数（单值真值在 `draw_control.cpp`，单位 mm、自底盘顶面量）：

| 参数 | 默认值 | 允许范围 / 相关宏 |
| --- | --- | --- |
| 纸面高度 `p<z>` | `DRAW_PEN_Z_DEFAULT = −6.0` | 任意有限值（只拒 NaN）；**必须上机重标**：z=0 是底盘顶面、臂尖最低只到约 −14，纸要垫高才够得着 |
| 图形半宽 `n<半宽>` | `DRAW_HALF_DEFAULT = 25.0` | `DRAW_HALF_MIN/MAX = 8.0 / 48.0` |
| 纸面中心 `o<x>,<y>` | `(0.0, 75.0)` | 每个轴的绝对值上限 `DRAW_CENTER_LIMIT = 140.0`（旧模型是 (27, 0)，已按新可达集重选） |
| 抬笔高度 | `DRAW_LIFT_DZ = 16.0` | 太高而不可达时由 `liftZFor()` 按 2.0mm 一档递减 |

**纸面为什么必须垫高、垫多高**（默认值不是拍脑袋，是 `.selfcheck/drawcheck.cpp` 打表选的）：
新臂长下卡住可用区域的是**关节行程**（`r 45~160`、`c 30~110` ⇒ `d ≤ 131.1`），
纸上每降低 1mm，纸面能用的半径就缩一圈。实测（`pathCorePointOk`，即路径校验用的判据；
x=0 沿 +y 扫 rho，步长 1mm）：

| 纸面 z (mm) | 可达 rho (mm) | 说明 |
| --- | --- | --- |
| −16 及更低 | 无 | −18 是 `limit` 盒子的下界，但那里只有"靠关节角吸附才能表示"的解 |
| −14 | 66~85 | 绝对下限，只能画半宽 ≤9 的小图 |
| −10 | 49~102 | |
| **−6（默认）** | **40~111** | 中心 (0,75)、半宽 25 → 整块方形 rho 50~103，两侧留 10/8mm |
| 0 | 30~121 | |
| +10 | 30~122 | 中心 (0,75) 可把半宽开到 35 |

也就是说：**纸铺在台面上是够不到的**（台面比底盘顶面低得多），要在纸下垫块
（垫块高度 = 台面到目标 z 的距离），用 `p<z>` 标定到"笔尖刚好触纸"为止；
想画大图就把纸垫得更高。整张 z→rho 表和候选 (纸面, 中心, 半宽) 矩阵由
`.selfcheck/drawcheck.cpp` 打印，改默认值前先跑它。

绘制速度与精度：`DRAW_V_MAX = 12.0` mm/s、加减速 `DRAW_ACCEL = 24.0` mm/s²、
单轮最大位移 `DRAW_STEP_MAX = 0.08` mm、轨迹校验采样 `DRAW_PATH_SAMPLE_STEP = 1.0` mm
（最多 `DRAW_PATH_SAMPLE_MAX = 256` 点）、过点判定 `DRAW_POINT_TOL = 1.0` mm；
示教点动每格 `DRAW_JOG_STEP_MAX / MIN = 1.0 / 0.08` mm。

- 流程：回待机 → 抬笔走位 → 落笔 → 绘制（梯形速度 + 关节速率限制）→ 抬笔 → 回待机；
  启动前对**整条轨迹**做完整校验（工作空间盒子 + 可达 + 不许夹取 + 相邻采样点关节角
  不许跳变），不过就拒绝且什么都不改。新模型的反解只有单分支，所谓"换分支"
  现在只剩"解被夹到行程窗口边界"这一种跳变。
- 示教：折线/曲线任务按 `D` 进入示教，摇杆笛卡尔点动（A0→x、A1→y、A3→z，前推 z 减小；
  A2 夹具默认不驱动，因为夹爪上夹着铅笔），串口 `G` 记点 / `E` 撤销，最多 5 点，
  满 5 点自动开始或按键 4 手动开始（至少 2 点）。
- 示教与绘制期间的按键：示教 1 记点 / 2 撤销 / 3 取消 / 4 手动开始；
  绘制中 1 暂停 / 2 继续 / 3 取消。500 轮无进展触发失速保护。

## 录制与回放

- 录制每 200 ms 一条，每条存 4 个轴的有符号增量（1 字节，0.5° 单位，满量程 ±128 并进位）。
- 上限 `WEARM_REC_ENTRIES = 192` 条 = **38.4 s**、768 B SRAM（固件里最大的静态缓冲）。
- 保存判据只看末端 x/y/z 位移 ≥ `BTN_REC_MIN_TRAVEL = 10.0`（新模型下就是 **10 mm**；
  旧模型里这同一个 10.0 是"10 个 4mm 单位"= 40mm，换了尺度以后这个门槛其实是变紧了）。
  "必须录满 10 秒"的旧要求已删；缓冲写满会自动停止并回 `DISCARD`。
  **重新录制会覆盖上一条**，哪怕新数据最终被丢弃。
- 播放先做 1500 ms 关节空间插值回到录制起点，再按每条 4 个子步回放；回中也用同样的 1500 ms 斜坡。

## 分支约定（v1.6.6 起）

> **容量数字的状态**：下面的 B 数都是 **v1.6.7（新运动模型）实跑 `.selfcheck/avr_build.ps1`
> 测出来的**（几种功能组合用 `-ExtraDefs` 消融，见脚本 `:24`）。分支策略本身没变：
> 一块板子一次只装一套功能。

取放模块按"8 步取放路径 + 物体高度自适应"重写后，**三个功能全开是 34648 B，
比 Uno 可用的 32256 B 多 2392 B**，Arduino IDE 会直接报 `Sketch too big`。
所以绘图模块被独立到 `draw` 分支，两边源码完全相同，只有 `weArm_config.h` 第 2 节
的两行开关数字不同：

| 分支 | 配置 | flash（v1.6.7 实测） | SRAM（v1.6.7 实测） |
| --- | --- | --- | --- |
| `pick_place`（本分支） | 取放 + 按键，绘图关 | **22734 B（69.4%）**，余 9522 B | 1236 B（60.4%） |
| `draw` | 绘图 + 按键，取放关 | **28824 B（88.0%）**，余 3432 B | 1447 B（70.7%） |

切分支 → 重新编译 → 重新烧写即可切换功能（一块板子一次只能装一套）。
想在一个固件里同时要取放和绘图：关掉按键模块（**31242 B，95.3%，装得下**），
代价是串口 `N/R/P/M/0` 的录制/回放/回中/循环取放全没了。

容量（Uno 可用 flash 32256 B / SRAM 2048 B；下表全部是 **v1.6.7 实测**）：

| 配置 | flash | SRAM |
| --- | --- | --- |
| 取放 + 按键 + 绘图 | 34648 B（105.7%）**装不进 Uno** | 1486 B（72.6%） |
| 取放 + 绘图 + 按键关 | 31242 B（95.3%） | 569 B（27.8%） |
| 取放 + 按键 + 绘图关（本分支默认） | **22734 B（69.4%）** | 1236 B（60.4%） |
| 绘图 + 按键 + 取放关（`draw` 分支默认） | 28824 B（88.0%） | 1447 B（70.7%） |
| 三开 + `-mrelax`（仅供参考） | 34128 B（104.2%）**仍超限** | 1486 B（72.6%） |

各分支都用 Arduino IDE 原样的链接参数就装得下，**不需要 `-mrelax`**。
（换用 Arduino 原生 `Servo` 库那一轮曾一度 32586 B 超限，靠收敛串口回复层、
把 `validatePath()` 曲线段的采样改走共用的 `pathCoreSegmentOk()` 等清理腾出了空间；
v1.6.6 的旧模型那轮取放重写花掉 2516 B —— 增量花在新路径本身，不是内联或冗余。
v1.6.7 换模型 + 重标点位后比 v1.6.6 时代大 180 B，属正常波动。）

单文件版与多文件版几乎相同（v1.6.7 本分支实测 **22754 B / 1236 B**，比多文件版多
20 B —— 合并成单个 TU 后 LTO 的内联结果略有不同，属正常）。
**上机状态**：v1.6.7 的运动学方向**已经上机验证过** —— 烧录后位置正确，
三条映射（`θ = b−90`、`α = 180−r`、`β = c`）与实物姿态一致，
**不需要 `mB`/`mS`/`mE` 换向**（`WEARM_MIRROR_BASE = 1` 默认即对）。
仍未标定的是：纸面高度 `p<z>`、绘图点动反向 `DRAW_JOG_INVERT_X/Y/Z`、摇杆方向语义、
`KIN_RARM/FARM` 行程真值、调速手感 —— 完整清单见 `.selfcheck/README.md`。

## 常见坑

1. **`x,y,z` 是三舵机角度**，不是末端坐标；坐标版在 `backup/xyz-cartesian`（tag `v1.6.3`）。
2. 角度越界是**夹取**不是拒绝（各轴按自己的行程窗口夹：r 最低 45、c 最低 30）；
   只写部分轴合法；到行程就停，不顶死舵机。
3. 装配镜像只在 `writeServo()` 里做：基座 `180 − b`、夹爪 `210 − f`、上臂 `205 − r`、
   下臂 `140 − c`（后两个不是 180：`r` / `c` 的行程窗口不对称，写死 180 会把
   `r = 45` 映成 135 越界）。"发 `O` 反而夹紧"是装配问题，逻辑角才是真值；
   方向不对先用串口 `m` / `mB` / `mS` / `mE` 就地翻转试出正确组合，
   再回写 `weArm_config.h` 的 `WEARM_MIRROR_*`。
4. **物理按键默认完全不读**，D2 上是右摇杆 SW，全推会误触发按键 1 抢走手动控制。
5. 串口 115200-8N1，行尾可有可无（静默 300 ms 提交），但单字符命令一到就执行。
6. 忙时**不排队**，`O`/`S`/`x/y/z`/`A/B/C` 只会回 `BUSY`。
7. **单文件版是生成物**：`make_single.ps1` 会 LF-only 输出，并把 `draw_control.cpp` 里的
   `clampDouble` 改名 `drawClampDouble` 以免与别处重名；只改根目录源码。
8. 别把生成物当源码：`.selfcheck/out/**`、`build/nocomment/verify/**`、根目录 `p1.txt`。
9. 录制上限 38.4 s，且**重录会覆盖上一条**（哪怕新录制最终被 `DISCARD`）。
10. "没执行"至少 5 种：`BUSY` / `OFF` / `REJECTED` / `DISCARD` / `EMPTY`。
11. 夹爪角放宽到 0\~180°（电气行程）：旧的 60\~150° 软限位、`servoLimit` 配置、
    纸面高度标定范围都已删除，`isReachable()` 也不再单独查竖向。三个位姿关节的
    **机械行程窗口**（b 0\~180、r 45\~160、c 30\~110）才是真限位，由
    `constant_and_positions.h` 的 `KIN_*` 宏给出，所有写入路径（`moveJointStep()` 等）
    引用同一组宏，超出行程是**夹取**不是拒绝。末端笛卡尔盒子 `rangeLimit` 随运动学
    一起换成了新尺度（**x/y ±160、z [−18, +171]**，即几何外包围盒 + 实测可达竖直带），
    但可达半空间只有 `y ≥ 0`、且 `z > 198` 永远无解，所以它**拦不住任何真实姿态** ——
    真正的判据是反解的距离 / 奇异 / 行程 / 5mm 回代残差，配置见
    `constant_and_positions.h` 的 `struct rangeLimit`。
12. 含中文的 `.ps1` 必须存成 **UTF-8 带 BOM**（`.selfcheck/ensure_bom.ps1` 可修）；
    提交信息与 Release 正文里的中文要用 UTF-8 无 BOM 文件配 `-F` 传入，走命令行会被 ANSI 重编码。
