# meArm 四自由度机械臂固件（Arduino Uno）

一套跑在 Arduino Uno（ATmega328P，16 MHz）上的完整固件：摇杆手动 + 串口控制 + 三物体自动取放
+ 7 种绘图任务 + 录制回放，附带 PC 端 11 个回归探针与 AVR 真编容量记录。

当前开发版 **v1.6.5**（尚未打标签）；上一发布版 [v1.6.4](https://github.com/2122019145/meArm/releases/tag/v1.6.4)。

**一套源码，两种交付形态：**

- **多文件版**：仓库根目录 21 个文件（`meArm.ino` + 9 个 `.cpp` + 11 个 `.h`），工程形态，日常开发只改这里；
- **单文件版**：`single/meArm/meArm.ino`（301756 字节 / 6713 行，LF），由
  `.selfcheck/make_single.ps1` 从多文件版**生成**，交作业/考试直接交这一个文件。

> 单文件版是生成物，不要手改。改完根目录源码后必须重跑 `make_single.ps1`，
> 否则 `.selfcheck` 里的 `wearm_ino_test` 探针会立刻失败。

详细设计说明（1500+ 行中文，含每个决策的理由与上机确认清单）在
[`.selfcheck/README.md`](.selfcheck/README.md)。

## 硬件与接线

| 部件 | 引脚 | 说明 |
| --- | --- | --- |
| 基座舵机 b（angle1） | **D9** | 回转，物理行程 0~180° |
| 上臂舵机 r（angle2） | **D8** | 俯仰，物理行程 0~180° |
| 下臂舵机 c（angle3） | **D7** | 俯仰，物理行程 0~180° |
| 夹爪舵机 f（angle4） | **D6** | 电气行程 0~180°；名义张开 150°、合拢 60°、夹紧 55° |
| 左摇杆 X | **A0** | → 基座 b |
| 左摇杆 Y | **A1** | → 上臂 r |
| 右摇杆 X | **A2** | → 夹爪 f（绘图示教点动时默认不驱动） |
| 右摇杆 Y | **A3** | → 下臂 c |
| 指示灯 | **D13** | 板载 LED：任一关节在动则快闪，全部静止则灭 |
| 四个物理按键 | D2\~D5 | 默认**完全不读**（`WEARM_BUTTON_PINS=0`），功能全走串口孪生命令 |
| 串口 | D0/D1 | **115200-8N1**，行尾可选，静默 300 ms 即提交该行；单字符命令一到就执行 |

- 舵机由 **Arduino 原生 `Servo` 库**驱动（标准 20 ms 一帧，4 路）；v1.6.6 之前是
  Timer1 硬件 PWM 直驱（30 ms 帧），换回原生库是为了夹爪堵转时保持力矩更稳，
  代价约 +1200 B flash。`servo_drive` 仍是唯一出口，换实现只改那一个文件。
- 基座与夹爪是**反向装配**，在唯一出口 `writeServo()` 里做镜像：基座 `180 − b`、
  夹爪 `TOOL_MIRROR_SUM(210) − f`；换装配只改 `WEARM_MIRROR_*`，逻辑角不用动。
- 上臂/下臂的引脚在 v1.6.5 开发中调换过（现固件为 ch1 = D8 上臂、ch2 = D7 下臂）；`setup()` 已按此接线绑定。
- 上机若出现某个关节抖动，优先排查舵机供电与共地，而不是先改固件
  （分析见 `.selfcheck/README.md` 的抖动附录）。

## 运动学模型

柱面坐标 + 平面两连杆。**几何参数：上臂 L1 = 下臂 L2 = 20，下臂末端相对肩部不外伸
（`armheight` = 0）**；长度单位与臂长定义一致（本例按 20 标定），角度一律用度。
原点取在肩关节（基座回转轴与上臂俯仰轴的交点），z 轴竖直向上，x/y 为水平面，
x 为开机面朝方向。

**关节角约定**（舵机中立位 90°）：

| 符号 | 含义 | 与舵机角的关系 |
| --- | --- | --- |
| b | 基座回转 | `θ = 90° − b`（b = 90° 时面朝 +x） |
| α | 上臂绝对方向角（从 +x 起算，地面参考） | `α = 90° − r`（r = 0° 竖直朝上、90° 水平朝前、180° 竖直朝下） |
| β | 下臂绝对方向角（地面参考） | `β = c − 90°`（c = 0° 竖直朝下、90° 水平朝前、180° 竖直朝上） |
| f | 夹爪 | 只驱动末端夹具，不参与正反解 |

> **修正历程**：肩、肘两个舵机都是"地面参考"的绝对角（与官方 MeArm 库
> `ik.cpp` 的 `a1`/`a2` 同构）。v1.6.5 及以前写成 `α = r`、`β = r − c`，把
> 「r=0, c=90」算成"上臂水平朝前"，而真机实测是"上臂竖直朝上、小臂竖直朝下"。
> v1.6.6 先把肩轴修成 `α = 90° − r`，但肘轴写成 `β = c − 180°`，把"下降"反解成
> "上升"——正是取放过程上下方向搞反的根因；最终按 RC-robot-hand 参考工程实测位姿
> （提臂只改 F(D7) 且 F↑=末端升、收臂 R(D8) 且 R↓=末端升）定为 `β = c − 90°`。
> 详见 `.selfcheck/README.md` 的"运动学标定"一节。

**正解**（`constant_and_positions.cpp` 的 `recFromServo()`；α/β/θ 用弧度）：

```
α   = 90° − r
β   = c − 90°
x_p = L1·cos(α) + L2·cos(β)          # 平面内半径
z = L1·sin(α) + L2·sin(β) + armheight
θ   = 90° − b
x   = x_p·cos(θ) ,  y = x_p·sin(θ)
```

**反解**（同文件 `getAngleEx()`，只用余弦定理，无迭代）：

```
ρ = √(x² + y²) ,  ζ = z − armheight ,  R² = ρ² + ζ²
δ = ±acos( (R² − L1² − L2²) / (2·L1·L2) )      # cos 先夹到 [−1, 1]；δ 是两杆几何夹角
b = 90° − atan2(y, x)  或  90° − atan2(−y, −x)  # 平面朝前 / 反折两个分支
β = atan2(ζ, ±ρ) − atan2( L2·sin(δ), L1 + L2·cos(δ) )
α = β + δ
r = 90° − α ,  c = β + 90°                      # 再按 360° 周期折回（见下）
```

正/反平面 × `δ = ±acos` 共 **4 个候选分支**，优先级「`+acos` 两族 > `−acos` 两族」，逐个正解回代求残差
`err = |fkPlanar(α, β) − (ρ, ζ)|`；只保留 b/r/c 都落在 **[0°, 180°]**（±1e-9）且 **err ≤ 0.05** 的候选，
先比优先级、同优先级内再取 err 最小者；一个都不合格才算反解失败，失败时**一个字节都不改**
（契约：失败时姿态保持原样）。角度的微小负值（> −1e-9）归零。

> **为什么按优先级而不是"只取残差最小"**：两杆平面机构对同一个点本来就有两个镜像解
> （`δ = ±acos`）。在这个模型下两个解都能落进 r/c 的 0~180° 行程，残差又都是 0，
> 于是"取残差最小"会靠浮点尾数随机挑一个 —— 同一条直线上相邻采样点来回换分支，
> 关节角一次跳 60~80°，取放/绘图的"段内不许换分支"校验必然失败（实测见
> `.selfcheck/README.md`）。修复前的固件里 `c` 就是 δ、且受 c ∈ [0,180] 限制，
> 等效于只允许 `+acos` 这一族，所以这里优先取同一族、只在它整族都不合格时才退到
> `−acos`（否则会把 `r=0 / c=0` 这类"臂折到极限"的可达点误判成不可达）。

> **为什么还要把 r/c 折回 360° 周期**：`α − β` 在本模型下等于 `180° − r − c`，
> 范围 `[−180°, 180°]`；反解里的 `atan2` 分支会把 `β` 落在 `[−180°, 180°]`，
> 对应 `c = β + 90°` 可能落到 `[−90°, 270°]`，`normRevAngle()` 把贴 360° 的值
> 折回 0°、把负值折进 `[0°, 360°)`，b/r/c 三轴共用。基座 b ∈ [0°, 180°] 只覆盖
> 前半空间，所以 `x < 0` 的点反解失败（可达包络是 x[0,40]、y[-40,40]、z[-40,40]）。

**可达性**（v1.6.5 起）：`isReachable()` 只检查水平半径 **ρ ≤ L1 + L2 = 40**（容差 1e-9）；
竖向不再单独设卡，能否走到由反解残差与路径校验把关。

**关节角是唯一真值**：摇杆、串口、按键、取放、绘图五条入口最终都只改 `Pos.ser.angle1..4`，
再调 `recFromServo()` 刷新派生坐标 `Pos.rec`（只用于显示与工作空间校验）；
笛卡尔移动统一走 `moveToPoint()`，各轴硬行程 0~180° 在 `moveJointStep()` 里。
初始位姿 `POS_HOME = (40, 0, 0)`，对应关节角 (90, 90, 90)、夹爪半开 105°（两节水平朝前、完全伸直的姿态，正好落在可达外边界 ρ = L1 + L2 = 40 上；这是用户标定的上电初始状态）。

> **注意语义变迁**：串口 `x,y,z` 写的是**三个舵机角度，不是末端坐标**。
> v1.3.0\~v1.6.3 曾是末端坐标版本，备份在分支 `backup/xyz-cartesian`（即 tag `v1.6.3`）与 `dist/`。

## 控制方式

### 摇杆（默认启用的手动方式）

一路摇杆轴对应一个关节，可同时操作：

| 摇杆轴 | 关节 | 方向 |
| --- | --- | --- |
| A0（左手柄左右） | 基座 b | 角度增大 → 末端往 +y 转 |
| A1（左手柄前后） | 上臂 r | 前推 = 角度减小 |
| A3（右手柄前后） | 下臂 c | 前推 = 角度减小 |
| A2（右手柄左右） | 夹爪 f | 角度增大 = 张开；推右 = 夹紧 |

- 每格位移 = `speed.stepSize × 偏转幅度/500`，关节下限 0.1°；步间间隔固定为 `speed.stepDelayMs`
  （推得狠一步更远，节奏不变）。
- 中位在开机时自标定（每轴平均 32 次 ADC）；标定期间不要碰摇杆。
- 防乱摆四层：死区 40、开机自标定、运行期 ±1 计数慢跟踪、施密特迟滞。
- 取放 / 录制回放 / 绘图期间摇杆整体让位；录制期间摇杆照常可用。

### 串口

115200-8N1。同一行里所有轴一起写入并只刷新一次正解；未写的轴保持不动。
**取放、录放、绘图期间不排队**：只接受"活字符"（见下），其余命令直接回 `BUSY`。

### 物理按键（默认关闭）

本工程把按键功能全部做成串口孪生命令，物理按键默认连 `pinMode` 都不做 ——
因为 D2 上还接着右摇杆的 SW，前推到底会误触发"按键 1"抢走手动控制。
需要实体按键时用 `-DWEARM_BUTTON_PINS=1`：1 = 循环取放 A→B→C，2 = 录制开关，
3 = 播放，4 = 回中。

## 串口命令

| 命令 | 作用 | 回复 |
| --- | --- | --- |
| `O` / `S` | 夹爪张开（150°）/ 合拢（60°，不带夹紧过行程） | `OK <角度>` |
| `H` / `L` | 速度升 / 降一档 | `OK` |
| `x[,y,z]` | **写三个舵机角度**：x→基座 b、y→上臂 r、z→下臂 c。可带 `=`、可小数、可 ±、大小写不敏感、可只写部分轴、重复轴以最后一个为准；越界按 0~180° **夹取**（如 `x200` 写 180）而不是拒绝 | `OK` |
| `A` / `B` / `C` | 启动 A / B / C 取放序列 | `OK` 或 `BUSY` |
| `N` / `R` / `P` / `M`、`0` | 按键孪生：循环取放 / 录制开关 / 播放 / 回中（带尾巴一律 `ERR`） | `OK` / `BUSY` / `DISCARD` / `EMPTY` |
| `F` | 循环切换绘图任务 | `OK F=<tag>` |
| `D` / `G` / `E` / `Q` / `U` / `W` | 开始绘图 / 记示教点 / 撤销 / 暂停 / 继续 / 取消 | `OK`，或 `BUSY` / `REJECTED` |
| `p<z>` / `n<半宽>` / `o<x>,<y>` | 标定纸面：高度（默认 **−20.0**，即初始位姿末端 (40,0,0) 再往下 20 单位，任意有限值都接受）/ 图形半宽（2~12，默认 6）/ 中心（|x|,|y| ≤ 35，默认 27,0） | `OK` 或 `REJECTED`（且不改参数） |
| `!` | 查询已编译且启用的模块 | 恰好一行 `P=1 B=1 D=1` |
| `!P` / `!B` / `!D` | 运行时开关取放 / 按键 / 绘图 | 切换后回同一行；模块未编译则 `REJECTED` |
| 其他 | — | `ERR` |

回复原语一共 8 种，别只看 `OK` / `ERR`：

| 回复 | 含义 |
| --- | --- |
| `OK` | 命令已执行 |
| `OK <角度>` | 仅 `O` / `S`，附带夹爪当前角度 |
| `ERR` | 语法错（角度写坏、单字符命令带尾巴等） |
| `REJECTED` | 该功能**没编译进来**；或绘图轨迹校验不过 |
| `BUSY` | 看懂了，但机械臂在忙 / 取放启动被拒（状态零改动） |
| `DISCARD` | `R` 结束录制但数据不合格（无位移、无动作、缓冲满） |
| `EMPTY` | `P` 时没有任何录制数据 |
| `OFF` | 功能在固件里，但被 `!P` / `!B` / `!D` 关掉了 |

开机横幅会打印全部命令首字符：
`CMD OSHL 123 kK ABC NRPM0 FDGEQUW pno ANG x,y,z ! !P !B !D`。

**忙时仍接受的字符**（位图 `s_liveBits`）：`0 D E F G H L M N P Q R U W n o p`，
另有 `1`/`2`/`3`（旧调速别名）。也就是说忙时 `O`、`S`、`x/y/z`、`A/B/C` 一律回 `BUSY`。

## 自动取放

| 物体 | 取点 (x, y, z) | 放点 (x, y) | 位移 |
| --- | --- | --- | --- |
| A | (24.0, 15.0, −18.0) | (16.0, −14.0) | Δx −8，Δy −26 |
| B | (24.0, −12.0, −18.0) | (18.0, 16.0) | Δx −6，Δy +28 |
| C | (12.0, 20.0, −18.0) | (28.0, −6.0) | Δx +16，Δy −26 |

- `PICK_GRASP_Z = −18.0`（台面/取放高度，三点共用），`PICK_APPROACH_DZ = 30.0`
  （接近、撤离与平移的飞行高度）；放点 z 同样是 `GRASP_Z`。
- 夹爪三段角：开 = `TOOL_ANGLE_OPEN` 150°，名义合拢 = `TOOL_ANGLE_CLOSE` 60°，
  夹紧 = `TOOL_ANGLE_TIGHT` 45°（在名义合拢角基础上再往里压 **15°**，保证小物体也
  真的被夹到）。合爪分两步走：先用 60°/s 快合到名义合拢角，再用 12°/s 慢慢压到
  夹紧角 —— 一次快合到底会让爪面像楔子一样把物体挤出去。
  **夹紧之后到张开之前的每一帧都重申夹紧角**，防止夹持力衰减。
- 速率：慢 25 / 中 50 / 快 90 °/s；夹爪快合 60 °/s、压紧 12 °/s；每阶段停顿 600 ms；
  单段限时 180\~4000 ms；路径采样 0.5、最多 64 点、分支跳变阈值 25°；启动容差 10°。
- 12 个阶段：`idle → to-src-approach → descend-src → close-tool → squeeze-tool →
  dwell-close → lift → traverse → descend-dst → open-tool → dwell-open → retreat`。
- `pickPlaceStart()` 返回 0 启动 / −1 物体非法 / −2 已在跑 / −3 姿态或路径校验不过
  （−3 有两个来源：当前位姿不在它自己坐标的反解分支上，或路径上有采样点不可达）；
  拒绝时**一个字节都不写**；启动前会先把夹爪归位到张开角，避免"闭着爪子"压下去。

## 绘图

| 编号 | 任务 | `F` 标签 | 说明 |
| --- | --- | --- | --- |
| 0 | 直线 | `LINE` | 2 点 |
| 1 | 字母 N | `N` | 4 点 |
| 2 | 三角形 | `TRI` | 4 点（闭合） |
| 3 | 字母 Z | `Z` | 4 点 |
| 4 | 字母 V | `V` | 3 点 |
| 5 | 五点折线 | `POLY` | 示教 5 点 |
| 6 | 五点曲线 | `CURVE` | 示教 5 点，向心 Catmull-Rom 插值 |

编号即 `F` 的循环顺序。纸面：高度默认 −20.0（初始位姿末端 (40,0,0) 往下 20 单位；**`p` 现在只拒绝 NaN，标定范围已删**）、
图形半宽 6.0（仍限 2.0\~12.0）、纸面中心 (27.0, 0.0)（仍限 |x|,|y| ≤ 35.0）、抬笔高度 4.0。

- 流程：回待机 → 抬笔走位 → 落笔 → 绘制（梯形速度 + 关节速率限制）→ 抬笔 → 回待机；
  启动前对**整条轨迹**做完整校验（限制 + 可达 + 不许夹取 + 不许切换 IK 分支），不过就拒绝且什么都不改。
- 示教：折线/曲线任务按 `D` 进入示教，摇杆笛卡尔点动（A0→x、A1→y、A3→z，前推 z 减小；
  A2 夹具默认不驱动，因为夹爪上夹着铅笔），串口 `G` 记点 / `E` 撤销，最多 5 点，
  满 5 点自动开始或按键 4 手动开始（至少 2 点）。
- 示教与绘制期间的按键：示教 1 记点 / 2 撤销 / 3 取消 / 4 手动开始；
  绘制中 1 暂停 / 2 继续 / 3 取消。500 轮无进展触发失速保护。

## 录制与回放

- 录制每 200 ms 一条，每条存 4 个轴的有符号增量（1 字节，0.5° 单位，满量程 ±128 并进位）。
- 上限 `WEARM_REC_ENTRIES = 192` 条 = **38.4 s**、768 B SRAM（固件里最大的静态缓冲）。
- 保存判据只看末端 x/y/z 位移 ≥ 10.0（"必须录满 10 秒"的旧要求已删）；
  缓冲写满会自动停止并回 `DISCARD`。**重新录制会覆盖上一条**，哪怕新数据最终被丢弃。
- 播放先做 1500 ms 关节空间插值回到录制起点，再按每条 4 个子步回放；回中也用同样的 1500 ms 斜坡。

## 速度档

| 档 | 步长 / 间隔 | 手动名义角速度 | 取放速率 | 命令 |
| --- | --- | --- | --- | --- |
| 慢速 | 0.5° / 80 ms | ≈ 6.25 °/s | 25 °/s | `H`/`L` 降到 0 档 |
| 中速（默认） | 1.0° / 40 ms | ≈ 25 °/s | 50 °/s | 开机默认 1 档 |
| 快速 | 2.0° / 20 ms | ≈ 100 °/s | 90 °/s | `H`/`L` 升到 2 档 |

`H` / `L` 中途即时生效（取放序列运行中也生效）；`setSpeed(步长, 间隔)` 可直接写任意值，
档名会显示为"自定义"。

## 配置开关

`weArm_config.h` 的 9 个宏都可以用 `-D` 覆盖（`.selfcheck/run_all.ps1` 就是这么组合测试的）：

| 宏 | 默认 | 作用 |
| --- | --- | --- |
| `WEARM_DEBUG_SERIAL` | 0 | 1 = 6 个模块的中文调试日志（+9260 B flash），并退回 HardwareSerial |
| `WEARM_ENABLE_PICK_PLACE` | 1 | 取放 A/B/C |
| `WEARM_ENABLE_BUTTONS` | 1 | 录制 / 播放 / 回中 / 循环取放（串口 `N/R/P/M/0`） |
| `WEARM_ENABLE_DRAW` | **0** | 绘图与纸面标定（本分支默认关；绘图在 `draw` 分支，见下） |
| `WEARM_MIRROR_BASE` | 1 | 基座反向装配（`180 − b`） |
| `WEARM_MIRROR_TOOL` | 1 | 夹爪反向装配（`210 − f`） |
| `WEARM_BUTTON_PINS` | 0 | 0 = 完全不读 D2\~D5；1 = 四键 INPUT_PULLUP |
| `WEARM_REC_TICK_MS` | 200 | 录制采样周期 |
| `WEARM_REC_ENTRIES` | 192 | 录制条数（×4 B = 768 B SRAM） |

被关掉的模块，其头文件会退化成空 inline 桩，调用方代码不用改。
另外 `-DWEARM_SERIAL_ARDUINO=1` 可让串口退回官方 `HardwareSerial` 实现（逃生开关）。

## 构建与自检

Arduino IDE 直接打开仓库根目录（sketch 名 `meArm`）或 `single/meArm/` 即可；PC 端自检脚本
一律这样调用（本机没有 `pwsh`，用 Windows PowerShell 5.1）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .selfcheck\run_all.ps1
```

| 脚本 | 用途 |
| --- | --- |
| `.selfcheck/run_all.ps1` | 9 个编译单元 `-Wall -Wextra -Wshadow -Wconversion` **零警告** + 11 个回归探针 **ALL PASS** |
| `.selfcheck/avr_build.ps1 [-SketchDir ...]` | AVR 真编（avr-gcc 7.3.0 + core 1.8.8，`-Os -flto`）并打印 flash/SRAM |

| `.selfcheck/gh_release.ps1` | 发 Release（走 REST，不需要 `gh` CLI） |

## 分支约定（v1.6.6 起）

取放模块按"8 步取放路径 + 物体高度 ±10cm 自适应"重写后，**三个功能全开是 34542 B，
比 Uno 可用的 32256 B 多 2286 B**，Arduino IDE 会直接报 `Sketch too big`。
所以绘图模块被独立到 `draw` 分支，两边源码完全相同，只有 `weArm_config.h` 第 2 节
的两行开关数字不同：

| 分支 | 配置 | flash | SRAM |
| --- | --- | --- | --- |
| `pick_place`（本分支） | 取放 + 按键，绘图关 | **22554 B（68.8%）**，余 9702 B | 1235 B（60.3%） |
| `draw` | 绘图 + 按键，取放关 | **29048 B（88.6%）**，余 3208 B | 1447 B（70.7%） |

切分支 → 重新编译 → 重新烧写即可切换功能（一块板子一次只能装一套）。
想在一个固件里同时要取放和绘图：关掉按键模块（取放 + 绘图 = 31092 B，装得下），
代价是串口 `N/R/P/M/0` 的录制/回放/回中/循环取放全没了。

容量（Uno 可用 flash 32256 B / SRAM 2048 B，本轮工作区实测）：

| 配置 | flash | SRAM |
| --- | --- | --- |
| 取放 + 按键 + 绘图 | 34542 B（105.4%）**装不进 Uno** | 1485 B（72.5%） |
| 取放 + 绘图 + 按键关 | 31092 B（94.9%） | 568 B（27.7%） |
| 取放 + 按键 + 绘图关（本分支默认） | **22554 B（68.8%）** | 1235 B（60.3%） |
| 绘图 + 按键 + 取放关（`draw` 分支默认） | 29048 B（88.6%） | 1447 B（70.7%） |
| 三开 + `-mrelax`（仅供参考） | 34022 B（103.8%）**仍超限** | 1485 B（72.5%） |

各分支都用 Arduino IDE 原样的链接参数就装得下，**不需要 `-mrelax`**。
（换用 Arduino 原生 `Servo` 库那一轮曾一度 32586 B 超限，靠收敛串口回复层、
把 `validatePath()` 曲线段的采样改走共用的 `pathCoreSegmentOk()` 等清理腾出了空间；
本轮取放重写又花掉 2516 B —— 增量花在新路径本身，不是内联或冗余。）

单文件版与多文件版几乎相同（本分支实测 22574 B / 1235 B，差 20 B —— 合并成单个 TU 后
LTO 的内联结果略有不同，属正常）。
**本工程尚未在实体 Uno 上烧录验证过**，
上机确认清单见 `.selfcheck/README.md`。

## 常见坑

1. **`x,y,z` 是三舵机角度**，不是末端坐标；坐标版在 `backup/xyz-cartesian`（tag `v1.6.3`）。
2. 角度越界是**夹取**不是拒绝；只写部分轴合法；到行程就停，不顶死舵机。
3. 基座 / 夹爪**反向装配**（`180 − b`、`210 − f`）只在 `writeServo()` 里做；
   "发 `O` 反而夹紧"是装配问题，逻辑角才是真值。
4. **物理按键默认完全不读**，D2 上是右摇杆 SW，全推会误触发按键 1 抢走手动控制。
5. 串口 115200-8N1，行尾可有可无（静默 300 ms 提交），但单字符命令一到就执行。
6. 忙时**不排队**，`O`/`S`/`x/y/z`/`A/B/C` 只会回 `BUSY`。
7. **单文件版是生成物**：`make_single.ps1` 会 LF-only 输出，并把 `draw_control.cpp` 里的
   `clampDouble` 改名 `drawClampDouble` 以免与别处重名；只改根目录源码。
8. 别把生成物当源码：`.selfcheck/out/**`、`build/nocomment/verify/**`、根目录 `p1.txt`。
9. 录制上限 38.4 s，且**重录会覆盖上一条**（哪怕新录制最终被 `DISCARD`）。
10. "没执行"至少 5 种：`BUSY` / `OFF` / `REJECTED` / `DISCARD` / `EMPTY`。
11. 夹爪角已放宽到 0\~180°：旧的 60\~150° 软限位、`servoLimit` 配置、纸面高度范围、
    `isReachable()` 的竖向约束都已删除；b/r/c 的 0\~180° 硬编码在 `moveJointStep()`。
    末端笛卡尔盒子 `rangeLimit` 已恢复（x/y ±40、z −60\~60），但 x/y 与实测包络端值重合、
    z 比真实包络（−20\~40）还宽，所以它**拦不住任何可达姿态**；配置与两条越界路径见
    `constant_and_positions.h` 的 `struct rangeLimit`。
12. 含中文的 `.ps1` 必须存成 **UTF-8 带 BOM**（`.selfcheck/ensure_bom.ps1` 可修）；
    提交信息与 Release 正文里的中文要用 UTF-8 无 BOM 文件配 `-F` 传入，走命令行会被 ANSI 重编码。
