# meArm 按键板（第二块 Arduino UNO / Nano）

一块**独立的 Arduino** + 4 个按键，用有线串口控制机械臂主控板 —— 不联网、不用 WiFi。

```
  4 个按键 ──> 第二块 Arduino（消抖 + 单击/双击/三击/长按判定）──串口──> 机械臂主控
                    └── USB 调试口：看到"按了什么、发了什么、机械臂回了什么"
```

程序里有**两套预设**，编译期选一套（默认第一套）：

| 预设 | 配哪块固件 | 波特率 | 命令 |
|---|---|---|---|
| `PRESET_MEARM`（默认） | 本仓库 meArm 主线固件（`protocol_constants.h` 那一套） | **115200** | 单字符：`N O S M R P H L F D G E Q U W m` |
| `PRESET_TASK5` | `others/f/MeArm` 的 Task5 系列固件 | 9600 | 单字符：`1`..`8`（+ 长按 `?`） |

两者都是"命令字符串 + `\n`"，所以切换只改一个宏：配置区 `PRESET`，或命令行 `-DPRESET=2`。

## 1. 和原来那块 `KeypadBoard_Task5` 的区别

| | 原 `KeypadBoard_Task5` | 本程序 |
|---|---|---|
| 跟机械臂通话的口 | `Serial`（D0/D1） | 默认**软串口 D2(RX)/D3(TX)**；`ARM_LINK_SOFTWARE=0` 可切回 D0/D1 |
| USB 串口 | 被机械臂占用：插着线不能上传、也看不到回包 | 留作调试口：随时上传 + 能看到机械臂每一句回包 |
| 按键反馈 | 无 | 板载 LED(D13)：命令发出闪 2 下、无此映射闪 1 下、长按闪 4 下、开机闪 3 下 |
| 手势 | 单击/双击/三击 | 多一个**长按**（所以 4 键最多 16 条命令） |
| 开机动作 | 向机械臂发一句横幅（Task5 会回 `! 指令：…`） | **不发任何字符** |
| 改按键/加按键 | 改 `sendCommand()` 里的 if-else | 改 `KEYS[]` / `LONGS[]` 两张表 |
| 支持的固件 | 只有 Task5 | meArm 主线（默认）+ Task5（`-DPRESET=2`） |

消抖 `DEBOUNCE_MS 30`、连击窗口 `CLICK_WINDOW 350` 与原版一致；长按阈值 `LONG_PRESS_MS 700` 是本程序新增的。

## 3. 接线

**按键**（一端接引脚，另一端接 GND；用芯片内部上拉，不用外接电阻）

| 按键 | 引脚 |
|---|---|
| 键1 | D8 |
| 键2 | D9 |
| 键3 | D10 |
| 键4 | D11 |

**串口（默认软串口模式）**

| 按键板 | 机械臂主控 | 说明 |
|---|---|---|
| D2 (RX) | D1 (TX) | 交叉相接 |
| D3 (TX) | D0 (RX) | 交叉相接 |
| GND | GND | **必须共地**，否则收到的是乱码 |

这样按键板的 D0/D1（USB）空出来了：插着 USB 也能上传、也能看调试输出。

**串口（`ARM_LINK_SOFTWARE 0`，最稳）**：按键板 D0→机械臂 D0、D1→机械臂 D1、GND 共地。
代价是按键板的 USB 口就是这条串口线，**上传时要先把这两根线拔掉**，运行时也没有调试输出。

> ⚠️ **关于 meArm 主线的 115200**：软件串口在 16MHz AVR 上发 115200 一般可用，但**收**容易丢字符
> （回包转发可能少字）。要 100% 可靠有三种办法，任选一种：
> 1. 用 `ARM_LINK_SOFTWARE 0`（D0/D1 硬件串口，115200 完全可靠）；
> 2. 两边一起降到 38400：固件 `protocol_constants.h` 的 `PROTO_BAUD` 与这里 `ARM_BAUD` 同时改，
>    软件串口在 38400 是稳的（只有这一处真值，改完两边重编）；
> 3. 只发不收：`-DECO_ARM=0` 编译，按键板不解析回包。
> Task5 预设是 9600，没这个问题。

## 4. 预设 A：meArm 主线固件（默认）

命令字符的真值在 `protocol_constants.h`；能不能执行由固件侧判定（忙、模块没开都会回包告诉你）。

| 键 | 单击 | 双击 | 三击 | 长按 |
|---|---|---|---|---|
| **键1 D8** 取放/夹爪 | `N` 循环取放（A→B→C） | `O` 爪张开 | `S` 爪合拢 | `M` 回开机位姿 |
| **键2 D9** 录制/速度 | `R` 录制开始/结束 | `P` 播放上次录制 | `H` 速度升一档 | `L` 速度降一档 |
| **键3 D10** 指定物体 | `A` 夹取物体 A | `B` 夹取物体 B | `C` 夹取物体 C | `!` 查模块开关 |
| **键4 D11** 调试/方向 | `m` 查换向状态 | `mS` 上臂换向 | `mE` 下臂换向 | `0` 回开机位姿 |

命令含义（对着 `protocol_constants.h` 与 `serial_protocol.cpp` 核对过）：

| 命令 | 行为 | 回复 |
|---|---|---|
| `N` | 按键1 的串口孪生：按顺序夹 A/B/C（`pickPlaceStart`） | `OK` / `BUSY` |
| `M`（别名 `0`） | 按键4 的串口孪生：回开机初始位姿 | `OK` / `BUSY` |
| `R` / `P` | 按键2/3 的串口孪生：录制开始或结束 / 播放 | `OK` / `BUSY` / `DISCARD` / `EMPTY` |
| `O` / `S` | 夹爪张开（角度 150）/ 合拢（角度 60） | `OK #`（`#` 是当前夹爪角度） |
| `H` / `L` | 速度升/降一档 | `OK` |
| `A` / `B` / `C` | 直接取放指定物体（`N` 会依次循环这三个） | `OK` / `BUSY` / `REJECTED` |
| `m` / `mS` / `mE` | 查换向状态 / 上臂换向 / 下臂换向（运行时切换，默认取编译期值） | `S=<0/1> E=<0/1>` |
| `!` | 查三个模块的开关状态（`!P` / `!B` / `!D` 是开关本身） | `P=<0/1> B=<0/1> D=<0/1>` |
| `F` | 切换绘图任务：直线 → 字母N → 三角形 → 字母Z → 字母V → 五点折线 → 五点曲线 | `OK F=LINE｜N｜TRI｜Z｜V｜POLY｜CURVE` |
| `D` | 开始绘制（内置图形直接画；五点任务进入示教） | `OK D=<任务>`（v1.6.8 起带标签）/ `BUSY` / `REJECTED` |
| `G` / `E` | 记录 / 撤销一个示教点 | `OK` / `REJECTED` |
| `Q` / `U` / `W` | 暂停 / 继续 / 取消 | `OK` / `BUSY` / `REJECTED` |

> ⚠️ **和主控固件的配套关系（v1.6.8 起变了）**：主控的**默认**功能组合是
> 「取放 + 绘图，按键关」（`PICK 1 / BUTTONS 0 / DRAW 1`，31740 B），**按键模块被裁掉了**
> —— 上面表里属于按键模块的 5 个槽位（`N`、`M`/`0`、`R`、`P`）在主控上只会回 `REJECTED`。
> 想用这块按键板的全部功能，把主控改成「取放 + 按键（绘图关）」（22770 B，本板最初就是
> 照它设计的）或「绘图 + 按键」（29356 B）；三个功能全开 35162 B 装不进 Uno（可用 32256 B）。
> 默认组合下 `O/S`、`H/L`、`A/B/C`、`!`、`m/mS/mE` 都不受影响（它们不属于任何模块）。
> `REJECTED` = 模块没编进固件；`OFF` = 编进来了但被 `!B`/`!D` 运行时关了；`BUSY` = 主控正忙。
>
> 绘图模块在默认组合里**是开着的**，想把绘图放上按键，把 `KEYS[]`/`LONGS[]` 换成这两行即可：
>
> ```cpp
> { PIN_K3, 1, "F", "键3 单击 切换绘图任务" }, { PIN_K3, 2, "D", "键3 双击 开始绘制" },
> { PIN_K3, 3, "G", "键3 三击 记录示教点" },  { PIN_K4, 1, "Q", "键4 单击 暂停" },
> { PIN_K4, 2, "U", "键4 双击 继续" },        { PIN_K4, 3, "W", "键4 三击 取消" },
> // 长按：{ PIN_K3, "E", "键3 长按 撤销示教点" }, { PIN_K4, "!", "键4 长按 查模块开关" }
> ```

**没放上按键的命令**（需要数字，从电脑串口 / 串口助手发）：

* `p<纸面z>` / `n<半宽>` / `o<中心x>,<中心y>`：纸面标定，例如 `p-6`（默认纸面 z=-6.0，纸要垫块；详见主 README 的绘图一节）；
* `x/y/z<角度>`：直接写三个舵机角度，例如 `x90`；一行可写多轴（`x90,y90,z90`）；
* `!P` / `!B` / `!D`：运行期开关取放 / 按键 / 绘图三个模块（`!` 只是查询，这三个是**切换**）。

## 5. 预设 B：Task5 固件（`-DPRESET=2`）

映射与原 `KeypadBoard_Task5` 完全一致，按键语义见 `others/f/MeArm/任务五_四按键使用说明.txt`：

| 操作 | 发送 | 机械臂行为 |
|---|---|---|
| 键1 单击 | `1` | 进入示教模式 / 已在示教则记录一个点（最多 5 点） |
| 键1 长按 | `?` | 状态查询：`状态:n 示教点数:m  笔尖(x,y,z): x, y, z` |
| 键2 单击 / 双击 | `2` / `3` | 暂停（仅绘制中）/ 继续（仅暂停时） |
| 键3 单击 / 双击 / 三击 | `4` / `5` / `6` | 取消 / 折线（示教 ≥2 点）/ 曲线（示教 ≥3 点） |
| 键4 单击 / 双击 | `7` / `8` | 直线演示（6 坐标）/ 基础图形（字母 N） |

Task5 那侧的硬约束：`5`/`6` 只在示教模式下动作；`7`/`8` 只在待机时动作，绘制中会回 `! 绘制/示教中，忽略`；
每条命令它都会回显 `<< cmd: x`，可以拿来确认链路。

## 6. 改键 / 加键

只改第 2 节的两张表（命令是**字符串**，多字符命令也能直接放）：

```cpp
{ PIN_K4, 3, "!D",  "键4 三击 开关绘图模块" },   // 加进 KEYS[]（单击/双击/三击）
{ PIN_K2, "!P",     "键2 长按 开关取放模块" },   // 加进 LONGS[]（长按）
```

（`!` 单独一个是**查询**：回 `P=<0/1> B=<0/1> D=<0/1>`；`!P` / `!B` / `!D` 才是切换开关。）

想多接一个按键：配置区加 `#define PIN_K5 4`，再把它加进 `PINS[]` 与两张表即可（轮询不用改逻辑）。

& 'C:\Users\m2122\AppData\Local\Programs\arduino-ide\resources\app\lib\backend\resources\arduino-cli.exe' `

| 配置 | 附加宏 | Flash | RAM |

| UNO meArm 预设 + 不转发回包 | `-DECO_ARM=0` | 6 116 B（18%） | 975 B（47%） |

## 8. 调试输出（USB，115200）

```
=== 机械臂按键板（第二块 Arduino）===
预设：meArm 主线固件，机械臂串口 115200 8N1
机械臂串口：软串口 D2(RX) / D3(TX)；USB 调试口见上
消抖 30ms，连击窗口 350ms，长按 700ms
按键引脚：D8 D9 D10 D11 （另一端接 GND，内部上拉）
映射（16 条）：
  键1 单击 循环取放(A/B/C)  → "N"
  ...
就绪（LED 闪 3 下）。LED：命令发出闪 2 下 / 无此映射闪 1 下 / 长按闪 4 下。
[按键] 键1 单击 循环取放(A/B/C)  → 发送 "N"
< CMD OSHL ABC NRPM0 FDGEQUW pno ANG ! !P !B !D m mS mE
< OK
[按键] 键3 单击 切换绘图任务  → 发送 "F"
< OK F=LINE
[按键] 键1 长按 回开机位姿  → 发送 "M"
< BUSY                     ← 机械臂正在动，这条被拒绝了
```

`[按键] …` 是按键判定结果，`< …` 是机械臂回包（`ECHO_ARM 0` 时只保留前者）。
"按了没反应"看这里就能分清：按键没读到 / 串口没通 / 机械臂状态不接受这条命令。

回包含义：`OK` 收到并执行；`ERR` 语法错；`REJECTED` 看懂了但这次执行不了（如路径校验不过）；
`BUSY` 机械臂在动；`DISCARD` 录制被丢弃（位移不够/没动作）；`EMPTY` 没有可用录制；`OFF` 该模块被 `!P/!B/!D` 关了。

## 9. 常见问题

| 现象 | 原因/处理 |
|---|---|
| 机械臂一串乱码 | 没共地；或软串口两根线接反/接错脚；或两边波特率不一致（meArm 115200 / Task5 9600） |
| 按了没反应，也没有 `[按键]` | 按键接线错（要接引脚↔GND，靠内部上拉）；或引脚号被改了 |
| 有 `[按键] …` 但机械臂不动 | 1) D2/D3 到机械臂 D1/D0 没接好；2) 机械臂不接受该命令（会回 `BUSY`/`REJECTED`/`OFF`）；3) 机械臂没上电 |
| 回包缺字/乱字 | 软串口 115200 收包不稳：改用 `ARM_LINK_SOFTWARE 0` 或两边降到 38400（见第 3 节） |
| 双击总是变成两条单击 | 两次按击间隔超过 350ms；把 `CLICK_WINDOW` 调大（如 450） |
| 单击被识别成长按 | 按得久（>700ms）会触发长按；把 `LONG_PRESS_MS` 调大或设 0 关闭 |
| 上传报 `not in sync: resp=0x00` | 用的是 `ARM_LINK_SOFTWARE 0` 时 D0/D1 被机械臂占着：拔掉那两根线再上传 |
| 命令被回 `OFF` | 机械臂固件里那个模块被 `!P`/`!B`/`!D` 关掉了，先发同一条 `!P`/`!B`/`!D` 打开 |
| 长按没反应 | 那个键在 `LONGS[]` 里没有映射（只闪 1 下 LED） |

## 10. 已验证 / 未验证

* **已验证（编译）**：arduino-cli 1.5.1 + AVR core 1.8.8，`--warnings more` 下六种配置
  （含两套预设 × 软/硬串口）全部 exit 0、0 error、0 warning，占用见第 7 节表。
  **第二次独立复核（v1.6.8）**：绕开 arduino-cli，直接用 avr-gcc 7.3.0 + core 1.8.8 编出
  同样的 **Program 6 170 B / Data 975 B**；交付稿 `single/arduino_keypad/arduino_keypad.ino`
  （多了 30 行说明头）编出来**数字一模一样** —— 说明头是纯注释，改注释不动映像。
* **已验证（逻辑）**：把 `keysTick()` 的消抖/连击/长按判定逐行搬到 node（`keysim.js`，`node keysim.js` 可重跑），
  用 5ms 步长喂合成波形，**19 个场景全部通过**：键1 单击/双击/三击 → `N`/`O`/`S`；键1 长按 900ms → `M`（且不发 `N`）；
  键1 只按 600ms → 松开发 `N`；键2 三击 → `H`；键3 单击/双击/三击 → `A`/`B`/`C`；键3 长按 → `!`；
  键4 单击/双击/三击 → `m`/`mS`/`mE`；键4 长按 → `0`；
  键1 四击（表里没有）→ 不发；12ms 抖动 → 只算一击；键2 两次单击间隔 700ms → 两条 `R`；
  两键几乎同时按 → 各发一条；单击后长按 → `N`,`M` 两条。
* **配套关系（v1.6.8 起，上机前必看）**：主控默认组合 `PICK 1 / BUTTONS 0 / DRAW 1` 裁掉了
  按键模块，本板的 `N/M/0/R/P` 会回 `REJECTED`；用本板请把主控改成「取放 + 按键（绘图关）」
  22770 B 或「绘图 + 按键」29356 B。见第 4 节的 ⚠️ 与 `arduino_keypad.ino` 头部的注释。
* **未验证（需要硬件）**：与真实机械臂的串口收发、按键电气抖动、长时间运行。
